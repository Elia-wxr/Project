# Tarot JupyterLab 项目进度与后续安排

**当前阶段是可安装的开发版。** 侧栏、后端和本地保存已经接通，组员可以用现有安装包试跑。课程交付还要验证真实 Socrates、完成组员独立试装并修复发现的问题，最后发布到正式 PyPI，从公开版本安装复验。

## 已完成的内容

| 部分 | 目前能做什么 | 对应代码 |
| --- | --- | --- |
| 英文侧栏 | 输入问题、抽一张牌、显示正逆位和关键词，查看解读和最近一条历史。 | `frontend/src/sidebar.ts` |
| 前后端通信 | 侧栏通过五个 HTTP 请求完成连接检查、抽牌、解读、保存和读取。 | `frontend/src/api.ts`、`src/tarot_jupyterlab/app.py` |
| 后端调度 | 后端为每次抽牌生成一个 `session_id`。解读和保存都使用这个编号来找到当前记录。 | `src/tarot_jupyterlab/service.py` |
| 单牌和 AI | 复用已有的 78 张牌和解读模块。已验证模拟解读、超时恢复和 AI 未配置时仍可保存。 | `src/tarot_jupyterlab/cards.py`、`src/tarot_jupyterlab/ai/` |
| 最近一条历史 | 把问题、牌面和已有解读写到本地。重启后可以只读查看。写入失败时保留上一条。 | `src/tarot_jupyterlab/history.py` |

**已有验证记录。** 60 个 Python 测试通过。开发时在独立环境安装了重新构建的 wheel，并用浏览器走通抽牌、模拟解读、保存和重启查看。已有验证针对开发版和模拟模型，组内还需要另一位同学按 README 复跑一次，真实课程模型也需要单独验收。

## 课程交付还需要完成什么

- [ ] **真实 Socrates。** 用课程给出的地址、模型名和密钥，从侧栏生成一次真实英文解读。记录实际结果，并确认无配置或失败时还能抽牌和保存。
- [ ] **组员独立试装。** 由一位没有参与打包的组员在干净环境照 README 安装，验证抽牌、解读、保存和重启查看，记录自己遇到的问题。
- [ ] **修复并复验。** 优先处理安装失败、解读中断、页面按钮卡住和历史丢失。每个修复附一条测试结果或复现记录。
- [ ] **正式 PyPI 发布。** 确认发布账号、包名、版本及课程是否要求源码包。候选包试装通过后，上传正式 PyPI。由另一位同学按包名和版本安装，跑完主流程并提交验收记录。

首版按两周计划验收**英文侧栏、单牌、真实解读、最近一条历史和正式 PyPI 发布**。三牌阵、多条历史、导入导出和界面美化排到后续版本。

## 下一步怎么学、怎么做

D1 指小组约定的开工日。完整的接口契约、任务依赖和验收时间见 `Plan.md`。

| 时间 | 要学会和做完什么 | 交付证据 |
| --- | --- | --- |
| **D1–D3** | 每个人在自己的电脑上试装一次。用浏览器的 **Network** 找到 `draw` 和 `reading`，看问题怎么发出去、同一个 `session_id` 怎么传给下一步。C 最迟 D2 核对课程 Socrates 配置和访问权限，D 同时准备 PyPI 账号及备选包名。 | 一次试装记录，加一条请求截图或两句请求说明。课程账号有问题时记录实际错误。 |
| **D4–D5** | 对照源码走一遍请求链路。做前端的同学练按钮事件和 `await`，做 Python 的同学练输入校验、JSON 转换或编写测试。每人做一个小改动或一项可复现检查。 | 提交、测试输出或复现步骤。能讲清改了哪个文件、怎么确认改动生效。 |
| **D6–D8** | 从侧栏试真实解读，检查总结、单牌解释和建议。测试空白问题、解读失败和超时。核对失败后还可以继续操作，保存和重启时数据一致。 | 真实模型结果或具体阻塞，一份成功与失败用例的记录。 |
| **D9–D10** | 用另一位组员的干净环境按 README 试装。修复主流程问题，写清安装与课程配置。第 10 天确认候选源码版本。 | 独立试装记录、已修问题的复验结果和候选源码提交。 |
| **D11–D14** | D11 构建候选包并优先用 TestPyPI 试发。候选包通过后，D12 正式发布并从 PyPI 独立安装。D13 留给补丁与复验，D14 汇总提交。 | 正式 PyPI 版本链接、安装命令、源码版本和验收结果。 |

## 六个人怎么接手

| 人员 | 优先任务 |
| --- | --- |
| **A · Coding Agent，全量** | 负责后端接口、调度和构建。带大家看请求链路，协助定位真实 AI 和打包问题。 |
| **B · Coding Agent，半量** | 前几天集中负责侧栏和文案，检查等待、成功和失败状态。把启动和修改方法交接给 A。 |
| **C · 普通成员，全量** | 负责抽牌逻辑与测试、真实 Socrates 验证和独立试装，担任发布备份。 |
| **D · 普通成员，全量** | 负责保存、覆盖、重启恢复测试及正式 PyPI 发布。 |
| **E · 普通成员，机动** | 补边界测试，例如空白输入、连续点击和解读失败后的操作。 |
| **F · 普通成员，机动** | 按 README 走查安装与演示，记录卡点和改进建议。 |

必做工作由 A、B、C、D 保底，E 和 F 的任务可以独立验收。任务到期没有可运行结果时，按 `Plan.md` 的接手表交接。小组记录以提交、测试或试装结果为准。
